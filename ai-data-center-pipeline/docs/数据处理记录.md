## 三、对结论有影响的决定

这六条单独列出，因为它们每一条都能改变结论的数量级或方向。

**1. 把 98 行判为预测，而不是观测。**
观测不可能发生在未来。如果不切分：95 个站点会全部显示"已投运"，兑现率变成 100%。这是整份分析的地基，而不是可选步骤。

**2. 站点级用 `max` 而不是"最新一行"。**
Epoch 会回溯修订历史值，累计值偶尔下调（2021→2022 曾出现）。取 max 是为了不让"数据修订"被读成"算力消失"。代价是：如果某站真实缩减产能，本口径看不见——已在局限中注明。

**3. `planned` 包含实测行，而不是只取预测行。**
若只取预测行（定义 C），则只有 54 个站点有定义。附录 A 显示 C 与 B 完全相等，说明**"承诺最高值永远出现在预测行，从不来自实测行"**——这本身是一条可写进正文的结构性事实。

**4. 41 个"无扩张承诺"站点的处理。**
它们没有预测行，`planned` 恒等于 `actual`，兑现率必然是 100%。这是**构造性**结果，不是发现。若不剔除，站点兑现率中位数会被抬到 57%；剔除后（54 站）只有 21.6%。两种数字都在 `definition_sensitivity.csv` 里，正文必须说明用的是哪个。

**5. 年度序列必须逐年结转。**
构造"站点 × 年份"矩阵后，某站某年无观测要沿用上一年值。第一版漏了这一步，导致 2029、2030 年的承诺总量塌到 0（只有少数站点有未来行）。修完后曲线才闭合。

**6. 功率口径与算力口径必须分开报。**
同一份数据：IT 功率管线倍数 **2.689×**，总功率 **2.741×**，算力 **4.552×**。差额来自承诺隐含的算力密度更高（总功率口径 809 → 1344 H100e/MW，+66%）。只报一个数会被追问"你到底在说功率还是算力"。

## 四、复算方法与独立核验

**① 单站手算路径（Colossus 2）**

```
2025-02-28   H100e = 0          ← 首次观测（土地平整）
2025-10-19   H100e = 277,918    ← 首次投运
2026-06-15   H100e = 1,111,673  ← max(实测行) = actual
2027-02-25   H100e = 1,824,154  ← max(全部行) = planned
兑现率 = 1,111,673 / 1,824,154 = 60.9%
滞后   = 2025-10-19 − 2025-02-28 = 233 天 / 30.44 = 7.7 个月
```

可用 `python scripts/05_trace.py "Colossus 2"` 逐行复现。

**② 跨表核对**：站点表当前值 = 时间线最大实测值，**95/95 完全相等**（`audit.json` 第 8 项）。

**③ 跨口径恒等式**：两个管线倍数应同源于同一批容量。
`4.552 / 2.689 = 1.693`，而密度比 `1344 / 809 = 1.661`，相差 1.9%，来源是 GW 与 M 单位四舍五入。**两式同源，不是两套独立数据。**

**④ 年度表与站点表交叉**：`annual.csv` 中 2026 年 `cum_actual` 合计必须等于 `site_level.csv` 的 `actual_h100e` 合计（14.752 M），两者一致。

**⑤ 数据集不变量（12 项，全部通过）**

| 检查 | 结果 |
|---|---|
| 行数 = 567 / 站点数 = 95 | 567 / 95 |
| 两表站点集合一致 | 双向差集为空 |
| 无重复（站点, 日期） | 0 |
| 实测 469 行 / 预测 98 行 | 469 / 98 |
| `actual ≤ planned` 全站成立 | 无越界 |
| 快照值 = 最大实测值 | 95/95 |
| 实测行 H100e 缺失 | 3 行（站点与日期已记录） |
| Power ≥ IT 功率的行占比 | 100% |
| Power/IT 比值落在 1.0–1.6 | 99.4%（中位 **1.299**） |
| 水耗缺失率 | 83.8% |

**⑥ 两类敏感性**

- **定义敏感性**：7 种口径下兑现率 11.68%–50.85%，跨度大，必须在图注声明口径（`definition_sensitivity.csv`）。
- **冻结日敏感性**：−60/−30/0/+30/+60 天 → 19.47% / 21.11% / **21.97%** / 25.02% / 26.57%。±4pp 内稳定，但方向朝上（持续投运在发生），因此**引用时必须写数据截止日**。

## 六、与全组中心问题的对齐

**本部分能提供（交接给下一位）**

| 内容 | 位置 | 用途 |
|---|---|---|
| 95 个站点的首投运日期与投运时长 | `results/site_level.csv` 的 `first_op`、`span_months` | 与出货批次做"同批设备 → 投运"匹配的时点依据 |
| 站点级算力与功率 | `actual_h100e`、`power_mw_actual`、`it_power_mw_actual` | 功率侧分析的输入 |
| 功率字段口径 | IT 功率 14.203 GW / 总功率 18.230 GW，比值中位 1.299 | 供方向三复用，避免两边算出两个数 |
| 算力密度 | 实测 809 → 承诺 1344 H100e/MW（总功率口径） | 解释算力口径与功率口径差额的唯一桥梁 |
| 建设状态分类 | `results/site_stage.csv` | 判断"承诺是否已开工"的分组依据 |

**本部分需要上一位提供**：分季度出货批次（型号 / 精度基准 / 折算算力 / 额定功率）。有了它才能做"同一批芯片在何时何地形成投运容量"的匹配；没有它，出货账与投运账只能各自成立、无法闭合。

**本部分明确不做**：芯片效率与单位成本（方向一）、电力需求预测与能效分析（方向三）、水耗。理由是这三块在分工 PDF 中分别属于另两位，且所需数据不在本部分两张表内。
