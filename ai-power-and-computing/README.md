### 2.3 三条不可让步的处理规则

**规则一：0 值不是「小数据中心」，是「还没投运」。**  
469 行真实观测里，`H100 equivalents` / `Power (MW)` / `IT power (MW)` 的 **min 与 25% 分位全为 0**。能源效率是除法，分母为 0 无意义，必须过滤 >0：

```
df_clean_actual      = df_actual.dropna(H100e, Power)      & 两者>0   -> 300 行（主线）
df_actual_full       = df_actual.dropna(三列)              & 三者>0   -> 300 行（拓展）
```

**规则二：本数据集里「严格筛选」不损失样本。**  
`df_clean_actual` 与 `df_actual_full` 同为 300 行——`IT power` 的 1 条缺失与所有零值行，都被 `H100e`/`Power` 的零值条件一并覆盖了。对照口径的 358 行同理。答辩时主动讲，否则「严格子集」会被误认为样本更少、存在选择偏差。

**规则三：三个比值口径必须分开报。**

```
eff_total = H100 equivalents / Power (MW)        总功率口径能源效率（主指标）
eff_it    = H100 equivalents / IT power (MW)     IT 硬件口径能源效率
pue       = Power (MW) / IT power (MW)           配套基础设施开销（≥ 1）
```

三者共用一个分子。另需注意：3.4 的**「每兆瓦 IT 对应算力」与 `eff_it` 是同一个式子**，只是先逐行算、再按站点取均值/中位数并换了个名字，别当成两个指标重复汇报。

### 2.4 口径声明表（答辩先讲这一段）

| 指标                  | 定义                                                 | 单位       |
| ------------------- | -------------------------------------------------- | -------- |
| 等效算力                | `H100 equivalents`，由 8-bit OP/s 折算，混入 TPU/Trainium | H100e    |
| 总功率 / IT 功率         | `Power (MW)` 含 IT + 制冷 + 配电；`IT power (MW)` 仅算力硬件  | MW       |
| 总口径能源效率 `eff_total` | 等效算力 ÷ 总功率                                         | H100e/MW |
| IT 口径能源效率 `eff_it`  | 等效算力 ÷ IT 功率（= 每兆瓦 IT 对应算力）                        | H100e/MW |
| PUE                 | 总功率 ÷ IT 功率，越接近 1 配套越省                             | ×        |
| 皮尔逊 r               | **逐观测行**计算，非站点级、非聚合比值                              | —        |
| 正式 / 对照口径           | 仅真实观测（n=300）/ 含 projection（n=358）                  | —        |

**「能源效率」这个字段两张表里都没有**，是构造出来的比值——必须把分子分母写死，否则无法复现。这也是答辩第一个会被问的点。

## 三、核心结论

> 3.1–3.7 全部为**仅真实观测口径（n = 300 / 89 站点）**，括号内给出含预测行对照值；3.8–3.9 为第十、十一节结论。

### 3.1 三条可直接上 PPT 的结论句

1. **强绑定**：等效 H100 算力与总功率 **r = 0.885**（对照 0.895）、与 IT 功率 **r = 0.865**（对照 0.874）。算力规模是预判机房用电负荷最稳的单一信号——扩容前必须先算供电、制冷与能耗预算。
2. **PUE 不是能效的替代品**：PUE 与总口径能源效率只有 **r = 0.169**（对照 0.159），几乎无线性关系。降低配套能耗不会自动提升「每兆瓦能跑多少算力」，两件事要分开管。
3. **同样的 IT 投入，算力承载差异明显**：89 个站点按中位数排序后，每兆瓦 IT 对应算力约从 **188**（Alibaba Zhangbei）到 **2915**（OpenAI Stargate Michigan），站点主体集中在 **1000–1500**（38 / 89 站点落在该区间，站点中位数之中位数 1139.79），仍有十倍以上跨度。同等 IT 硬件功率下承载的算力并不一致，反映硬件配置与运行模式差异；完整分布以图 4（`output_51_0.png`）为准，不要只引用表内摘录值。

### 3.2 六组相关系数·冻结日切分前后核验

| 分析关系                      | 含 projection（n=358） | **仅真实观测（n=300）** | 变化     |
| ------------------------- | ------------------- | ---------------- | ------ |
| 等效 H100 总算力 — 总功率         | 0.895               | **0.885**        | −0.010 |
| 等效 H100 总算力 — IT 硬件功率     | 0.874               | **0.865**        | −0.009 |
| PUE — 总口径能源效率 `eff_total` | 0.159               | **0.169**        | +0.010 |
| 剔除宽松离群：算力 — 总功率           | 0.868               | **0.862**        | −0.006 |
| 收紧阈值剔除离群：算力 — 总功率         | 0.843               | **0.841**        | −0.002 |
| 收紧阈值剔除离群：算力 — IT 硬件功率     | 0.829               | **0.828**        | −0.001 |

> **结论**：剔除 98 行预测样本后，六组系数变化都在 ±0.010 以内，强弱关系完全没有改变——算力与功率依旧强正相关、PUE 与总能效依旧极弱相关。**核心相关性结论不依赖预测规划样本**。

### 3.6 三个反直觉发现

1. **PUE 越低不等于越「省算力电」**（r = 0.169）。PUE 只衡量配套开销，不含任何算力信息；一个 PUE = 1.10 但芯片老旧的机房，每兆瓦算力可能远低于 PUE = 1.35 的新机房。优化能耗不能只盯 PUE。
2. **剔除离群点后 r 单调下滑：0.885 → 0.862 → 0.841**。准确表述是「**方向稳健、强度被少数超大站点放大**」，不是「系数完全不变」。三档一起摆出来，比只报一个 0.885 更严谨。
3. **0.885 只属于「已投运」的机房**：过滤 >0 加冻结日切分，把规划期零值观测与 98 行未来排期都排除了，相关系数描述的是已上线站点的规律，不能外推到还在图纸上的机房。第十节的预测正是把这套「已投运」能效中位数外推到未来，所以它只能写成 **what-if 情景**，不能写成确定性用电预测；第十一节进一步用分层三情景刻画了这一不确定性。

### 3.8 正面回答：需要投入多少电力资源（第十、十一节）

课题第一问由**基准情景 + 三情景区间**共同回答。做法与前面分析一脉相承，仍读 n=300 的 `df_actual_full`（`timeline_cleaned_actual.csv`），取两套能效的中位数作基准：

```
基准  eff_it    中位 = 1019.10 H100e / MW-IT
      eff_total 中位 =  797.76 H100e / MW-总功率
情景  H_add = 48.0 M H100e（what-if 假设，非历史观测）
公式  IT_power_add = H_add / eff_it
      Power_add    = H_add / eff_total
```

**基准情景**：只算 GPU 服务器硬件就要 **47.10 GW**；叠加制冷、配电损耗，向电网取电要 **60.17 GW**，约为当前样本总功率 18.23 GW 的 **3.3 倍**。总 / IT = **1.2775**，与 PUE 中位 1.30 的独立校验（47.10 × 1.30 ≈ 61.23 GW）基本吻合。

**规模分层三情景**（第十一节，按全样本算力中位数 155,128.9 H100e 分组，小 / 大规模各 150 行）：

| 情景           | `eff_it` 中位 | `eff_total` 中位 | 新增 IT 功率                   | 新增总供电功率                    |
| ------------ | ----------- | -------------- | -------------------------- | -------------------------- |
| 保守（小规模，能效偏低） | 754.68      | 579.61         | 63,603.34 MW（63.60 GW）     | **82,814.31 MW（82.81 GW）** |
| **基准（全样本）**  | **1019.10** | **797.76**     | **47,100.20 MW（47.10 GW）** | **60,168.56 MW（60.17 GW）** |
| 乐观（大规模，能效偏高） | 1140.31     | 873.10         | 42,093.71 MW（42.09 GW）     | **54,976.36 MW（54.98 GW）** |

> 三情景给出 **54.98 – 82.81 GW** 的区间：未来新建机房的规模结构若与历史样本不同，电力需求会明显偏移。结论只能写「情景对应的功率」，不能写「预测实际用电」。

三条必须随结果一起讲的边界（第十节自列）：

- **what-if，不是确定性预测**：48.0 M H100e 是自设情景假设，不是历史已建成观测；核心假设是未来新建机房的能效分布与当前已投运样本一致。
- **方向不对称**：芯片能效提升或 PUE 下降 → 实际需求更低；新建机房运行能效更差 → 更高。
- **未计工程因素**：电网建设时序、负荷波动、工程冗余备份均未纳入，只作课题情景参考，不等同工程规划方案。

> 结果导出 `power_prediction_local.csv` 与 `three_scenario_prediction.csv`；三情景柱状图 `output_74_4.png` 已补齐。

### 3.9 规模效应：预测的适用边界（第十一节）

以 `H100 equivalents` 表征机房规模，与两套能效求皮尔逊相关（同一份 n=300 真实观测样本）：

| 分组                | 行数  | r（规模 — `eff_it`） | r（规模 — `eff_total`） |
| ----------------- | --- | ---------------- | ------------------- |
| 全样本               | 300 | **0.672**        | **0.656**           |
| 小规模组（≤ 155,128.9） | 150 | 0.319            | 0.322               |
| 大规模组（> 155,128.9） | 150 | 0.669            | 0.641               |

全样本明显正相关：**机房规模越大，单位功率承载的算力越高**。但分层后**小规模组的组内相关降到 0.32 左右**，说明全样本观测到的强相关**主要来自组间差异**——大、小规模机房本身属于两套建设标准，并不是「机房一变大就自动更省电」。

这一结论同时解释了为什么必须做三情景：直接用全样本中位数外推，等于假设未来新建机房的规模结构与历史样本一致；若未来以大机房为主，实际需求会偏向乐观情景。**分层检验 + 三情景区间**共同构成了预测的适用边界。

## 五、局限（PPT 必须写）

1. **相关 ≠ 因果**，且「站点规模」是算力与功率的共同因子，0.885 不能读成「提高算力就会按比例提高用电效率」。
2. **300 行是观测行，不是 300 个独立样本**：同一站点重复观测，冻结后有效独立单元只有 **89 个站点**，相关系数的显著性被高估。
3. **冻结过滤带来样本收缩**：567 → 469 → 300 行、95 → 89 站点，6 个站点完全消失，部分站点只剩 1 条观测（Stream Phoenix）。站点级均值与中位数都可能不稳，不宜过度泛化。
4. **皮尔逊对离群点敏感**：正式口径剔除极端样本后 r 从 0.885 降到 0.841；另 H100e 由 8-bit OP/s 折算、混入 TPU/Trainium，不能当「GPU 张数」读，「每兆瓦算力」是折算口径。
5. **样本非全市场**：Epoch 自述覆盖率 44%，美国 77/95、中国仅 5 站 → 所有结论限定「在本样本中」。
6. **结论只覆盖已投运 / 真实观测**：预测行已被剔除，不能外推到规划期机房。
7. **预测是 what-if 情景，不是确定性用电预测**：48.0 M H100e 为自设假设而非历史观测，核心假设是未来新建机房能效分布与当前已投运样本一致；芯片能效提升或 PUE 下降会让实际需求更低，运行能效变差则更高。电网建设时序、负荷波动、工程冗余均未纳入。
8. **规模结构会拉偏预测**：算力规模与 `eff_it` / `eff_total` 的 r = 0.672 / 0.656，但分层后小规模组组内相关仅 0.319 / 0.322，说明强相关主要来自组间差异。已用保守—基准—乐观三情景（54.98 – 82.81 GW）刻画该不确定性，但它仍只覆盖「规模分布」这一维，未覆盖芯片代际、PUE 演化等其他变化。
9. **芯片端能效传导不在本次范围内**：第十二节已界定该问题为分析范围之外，未开展实证计算；因此「芯片能效提升能否传导到机房层面」在本报告中无结论，预测也未显式考虑芯片代际迭代。
